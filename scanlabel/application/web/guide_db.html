DB 에 무엇이 어떻게 저장되나

scanlabel 은 자기 전용 PostgreSQL 에 사람이 정한 것(라벨), 본 기록의 모양 요약(기록 풀), 그것으로 계산한 묶음을 나눠 남깁니다. 라벨은 잃으면 안 되고, 풀과 묶음은 언제든 다시 만들 수 있습니다.

  • fleet(ftpmodule)의 DB 는 읽지 않습니다. fleet 의 값은 HTTP 로 받아 사본(meta · features)으로만 남깁니다.
  • 사람이 읽는 시각은 모두 KST ISO 문자열(2026-11-03T06:58:39+09:00)입니다.
  • 컬럼의 정본은 scanlabel/data/migrations/*.sql 이고, 이 페이지는 그것을 읽는 지도입니다.

3 라벨

label_defs · scan_labels

label_defs — 분류 트리

  • 대분류 › 중분류 › 소분류 3단계 고정(level 1·2·3). 한 테이블이 parent_id 로 자기를 가리킵니다.
  • 같은 부모 아래에서만 이름이 유일(대소문자 · 공백 무시) — 「피크」가 서로 다른 대분류 아래에 각각 있을 수 있습니다.
  • 지우지 않고 retired 로 은퇴시킵니다. case_id 는 fleet 사례를 가리키는 soft 참조(조인하지 않음).
  • 실제 분류표 ID-0603 은 마이그레이션 0003 이 넣습니다.

scan_labels — 기록에 붙인 라벨

  • label_ids bigint[] — 하나 이상, 어느 단계든. 배열이라 외래키가 아니고, 저장 전에 서버가 검사합니다.
  • features 를 복사해 둡니다 — 원본이 fleet 캐시에서 사라져도 닮은 기록 찾기가 됩니다.
  • 라벨을 비우면 행을 삭제합니다. 저장은 항상 fleet 에서 새로 읽어 그 시점의 세대를 남깁니다.

4 기록 풀

scan_records · index_cursors
  • scanlabel 이 본 기록마다 모양 요약을 한 벌 둡니다. 라벨이 없어도 들어옵니다. 묶음은 이 테이블만 읽습니다.
  • 풀에 들어오는 길은 셋: 화면에서 파일을 열 때 · 라벨 저장 · jobs index(fleet /generations 를 따라가며, 캐시만 읽음).
  • scan_enum · chuck_id · sensor_id 세 열이 묶음 범위입니다. 범위마다 따로 묶습니다.
  • index_cursors 는 jobs index 가 어디까지 읽었는지(after_id). 도중에 실패해도 처리한 데까지는 남깁니다.

seq — 「묶음이 낡았다」를 아는 법

같은 파일을 다시 열어도 세대 · 요약 판 · 스캔 종류 · 척 · 센서가 그대로면 행을 쓰지 않습니다. 바뀔 때만 새 seq 를 받습니다. 묶음 판은 묶을 때의 최대 seq 를 pool_seq 로 기억하므로, 풀에 그보다 큰 seq 가 있으면 「낡았다」고 화면이 말합니다. 열기만 해서는 낡아지지 않습니다.

5 모양 요약 features

jsonb

scan_labels 와 scan_records 의 features 는 같은 모양입니다. 정규화 전 값만 남기고, 비교용 정규화는 읽을 때 합니다 — 그래서 비교 방식을 바꿔도 원본 없이 요약만으로 다시 계산됩니다.

{
  "version": {{FEATURE_VERSION}},                        // 요약 모양이 바뀌면 올린다 (jobs refeature)
  "channels": {
    "tr": {                                // 채널 이름은 dump 의 value 키 그대로
      "path":  [ ... {{PATH_N}}개 ... ],           // 측정 순서 곡선을 {{PATH_N}}점으로 줄인 것
      "grid":  [ ... {{GRID_N}}×{{GRID_N}} 칸, 빈 칸은 null ... ],   // 선 스캔이면 null
      "stats": { "n": .., "min": .., "max": .., "mean": .., "std": .. }
    }                                      // txh, tyh … 채널마다
  }
}

feature_version 이 코드의 값과 다르면 낡은 요약입니다. 배포 뒤 jobs refeature 가 라벨된 기록과 풀을 새 판으로 바꾸고, 이어서 jobs cluster 를 돌립니다.

6 묶음

cluster_*
  • 묶기는 (스캔 종류, 척, 센서)마다 따로 합니다. 한 범위에서 라벨된 기록 전부 + 라벨 없는 최근 {{CLUSTER_MAX_N}}건을 묶고, {{CLUSTER_MIN_SIZE}}건 미만 무리는 묶음이 아니라 「묶이지 않음」입니다.
  • 잣대 둘 — skew(채널 간 편차) · pca(주성분). 같은 풀을 두 잣대로 따로 묶어 각각 저장하고, 화면이 골라 봅니다.
테이블키담는 것
cluster_runsid계산 한 번. (set_name, method)마다 최신 한 판. 기록 수 · 묶음 수 · 묶이지 않은 수 · pool_seq · next_no · changes(지난 판과의 차이)
cluster_membersrun_id, record_id묶음에 든 기록. cluster_no · 대표와의 유사도 score · representative. 묶이지 않은 기록은 행이 없음
cluster_pointsrun_id, record_id묶어 본 기록 전부의 지도 2D 자리 x y
cluster_mapsrun_id, group_key범위 하나의 투영식(jsonb). 이것이 있어야 그 판에 없던 새 기록도 같은 지도에 놓습니다. 기준점 {{MAP_LANDMARKS}}개(skew) 또는 주성분 모델(pca)
cluster_shapesrun_id, cluster_no묶음의 평균 그림(평균 곡선 · 25–75 백분위 띠 · 칸 평균) — 목록 · 지도가 구성원을 매번 읽지 않게
  • 「라벨됐나」는 컬럼이 아니라 scan_labels 와 맞춰 그때그때 계산합니다. 라벨이 바뀌어도 묶음을 다시 쓰지 않습니다.
  • 번호가 이어집니다. 새 판을 저장할 때 같은 (set_name, method) 의 옛 판을 지우기 전에 옛 번호를 읽어, 닮음이 그대로인 묶음은 지난 번호를 이어받습니다. 번호는 재사용하지 않으므로 판마다 next_no 를 남깁니다.
  • 자식 테이블은 모두 run_id → cluster_runs 외래키(삭제 시 함께 삭제)입니다.

8 스키마 바꾸는 법

migrations
  • 새 파일 data/migrations/NNNN_*.sql. 적용된 파일은 절대 고치지 않습니다 — 파일 체크섬이 장부와 다르면 에러입니다.
  • 서버는 시작할 때 스키마 버전을 확인하고 다르면 시작을 거부합니다. 적용은 python -m scanlabel.data.migrate up.
